# Sweep, 5 October 2026: the issues reported, looked for everywhere

The reports that started it were each one screen: no success message after
adding a college, a class that did not appear in the student form because it had
no section, a field nobody wanted, a management screen that did not exist. This
sweep asked the same questions of every page, with an instrument for each rather
than by reading screens one at a time. Everything below was measured in
Northgate Test Annex, a college founded through the product, so it sees what a
new customer sees.

## 1. What a new college starts without (0332, 0333)

Compared every table in `public` between the seeded demo college and the
colleges `college_create` made. Four defaults were missing and each changed
behaviour silently:

| Missing | What it did | Fix |
|---|---|---|
| `roles.subject` | a parent or student login stood for nobody; "invite the parent" found no role | `reference.role_subject_defaults` + trigger on `roles`, backfilled (0332) |
| `weekends` | every Sunday was a working day: payroll prorated over it, attendance coverage reported Sunday registers missing | `reference.weekend_defaults`, trigger on `tenants`, backfilled where a college had none (0333) |
| `leave_types` | no member of staff could apply for leave | `reference.leave_type_defaults` for new colleges; an existing college gets *Add the usual kinds* on /hr/leave (0333) |
| `grading_schemes` | results computed with no grade bands and no pass mark | `reference.grading_scheme_defaults` for new colleges (0333) |

Leave types and grading schemes are deliberately not written into existing
colleges: they are a college's own policy.

## 2. A write path nobody can call

Every `export async function` in a `"use server"` module, checked for an import
anywhere in `src/`, resolved to the module it comes from. Eleven had no caller:

- cancelling an invoice, and raising one for a single student: buttons on the
  invoice and the fee account (`invoice-controls.tsx`);
- ending a hostel stay or cancelling a booking: *End stay* on the register;
- the kinds of staff leave: a card on /hr/leave;
- attaching a file to a notice, and removing one: an editor on the notice;
- deleting a book, a bus route, a schedule (only one that has never run: its
  register is the record) or an account: `ConfirmDeleteButton`, which shows the
  database's refusal in place;
- editing a posting rule: `PostingRuleDialog`;
- the enquiry follow-up log, written on every call and shown nowhere: now the
  top of the follow-up dialog.

`tests/app-shell/every-action-has-a-caller.test.ts` keeps it that way. Its
first, name-matching draft missed notices' `attachFile` because homework has an
action of the same name; it resolves imports now.

Wiring the buttons found three defects underneath them:

- **An invoice with a concession could never be cancelled** (0334). The
  function refused any invoice with a ledger entry, and a concession is a
  ledger credit against the invoice. Reversing it first could not help, since
  the reversal carries the same invoice id. It now refuses only for a
  payment, refund or adjustment, and reverses the concession credits itself.
  `fees_reverse_entry` also dropped `concession_award_id` on a reversal: the
  `0026`/`0265` omission, one column along.
- **A one-time fee was billed again by every invoice** (0336). The new
  *Raise invoice* billed ANX-0001's admission fee a second time, because an
  invoice without a billing period had no memory of the year. A `one_time` or
  `annual` fee already on an issued invoice this year is no longer billable, on
  every path; a cancelled invoice re-opens it.
- **Three checks linked to 404s** (0335): `/schedules` twice and
  `/notifications/templates`. `tests/app-shell/catalogue-links-resolve.test.ts`
  reads every href a catalogue migration writes.

## 3. A save with no message

Every client component calling a write action, checked for feedback within its
success path. Silent: the behaviour-trait switch, notification preferences,
the permission grid, skipping or re-targeting a renewal, preparing a renewal
list (it navigated away with nothing said, the shape of the *add college*
report), discarding an invitation list and the importer's class change. The
last two also ignored a failure. All now say what happened.

## 4. Created, then invisible

Pickers that read a child table and silently omit a parent without one, the
class-without-a-section shape:

- the admission form dropped its bus and hostel fields when routes or hostels
  existed with no stops or rooms; it now says which, and where to add them;
- a fee head with no amount for any class is billed to nobody; the fee heads
  list now says so (bus and hostel heads excepted: they are priced by stop and
  room);
- three forms filled a required field for the person without clearing an
  earlier error on it (timetable teacher, compose channels, and the admission
  section fixed in 0331's round).

Subjects were already safe: since 0275 a subject cannot be created without its
classes.

## 5. Every page, opened

94 routes as the administrator of the Annex, recording HTTP status, page
errors, console errors and error-boundary text: no crash and no error screen.
The 404s in section 2 came from here. One console error on ID cards is this
sandbox's TLS proxy refusing the photo's signed URL, not the app.

Page times in the sandbox ranged from 8 to 30 seconds for the same page between
runs, while a bare round trip to the database measured 0.2 to 0.4 seconds; a
page makes many such calls through the sandbox proxy. That is the environment,
so no code was changed for it, and no claim is made here about production
timings.

## 6. Matching the remaining lists to the reference (0337)

Three columns the reference shows were facts this schema did not hold: a
book's number and price, and an exam's centre. 0337 adds them; the book number
is unique in a college when given, and the centre is printed on the admit
card. The catalogue read is a new function, `library_catalogue`, because
`library_books` returns a fixed table type and replacing it needed a drop,
which the tool used to apply migrations held without it reaching the database
(the database log shows none of the attempts). `library_books` is left with
no caller and a comment saying so, for a later migration to drop.

Two defects were under the lists being reworked:

- **Editing a vehicle cleared its in-charge.** The dialog had no field for the
  attendant and always sent an empty one, so the attendant could never be set
  and a save wiped one set any other way. The dialog has an In-charge field
  now and sends the vehicle's own value.
- **Editing a book did not check that anything was written** (rule 6). It now
  reads the row back and says so when nothing matched.

One found and not fixed, because it needs its own change: the Books Issued
search filters only the page already loaded, so a title on page 2 is not found
from page 1. The search has to move into the query.

Walked in the Annex as its administrator: a book created with a number, price
and rack, found by its number, a duplicate number refused, issued from the
catalogue's Issue Book column (quantity 3/3 to 2/3 without a reload) to a
library card issued from Library Cards, the card printed, and the issue shown
with enrollment number, class and section; an exam created with a centre and
its Results link opening the Results tab; a vehicle, a hostel and an item
created and shown under the new columns. The admit card's centre line was
checked by type and build only, because the Annex exam has no papers.
